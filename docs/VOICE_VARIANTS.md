# LUMEN — грамматика вариативного произношения (без LLM)

Статус: архитектурные требования для реализации; сам генератор грамматик/морфологии пока не интегрирован с `js/command-engine.js`. Основание — пожелание максимально большого числа естественных формулировок **при отсутствии неоднозначных побочных эффектов**.

## Модель

`utterance → normalize → detect control/negation → anchored phrase family → parse typed slots → entity resolution → collision check → permissions → optional confirmation → verified adapter result`.

### Источники вариативности

| Источник | Пример | Ограничение |
|---|---|---|
| Действие | «открой» / «запусти» / «включи» | Контекстная группа, не глобальная подмена «включи» |
| Имя сущности | «Steam» / «стим» | Только явно сопоставленные алиасы реестра |
| Синтаксис | «Steam открой» / «Открой Steam» | Два явно разрешённых шаблона |
| Вежливость | «Пожалуйста, запусти Steam» | Только явные вводные конструкции |
| Разговорные формы | «выруби комп» → `system.shutdown` | Только подтверждаемое действие, никакого fuzzy-autostart |
| Числа | «экран два» / «второй монитор» | Один typed display ID, проверить число экранов |
| Местоимения | «его», «туда», «это окно» | Только живой объект активного контекста, иначе уточнение |
| Пунктуация и «ё» | «открой, пожалуйста, стим» | Без удаления отрицаний и смысловых слов |

## Технические правила будущего phrase-family expander

1. Генерировать конечное число явно допустимых шаблонов с лимитом на одну команду и общий реестр (например, 128/2048); никакого неограниченного декартова произведения.
2. Дедуплицировать нормализованные формы внутри ID; совпадение разных ID — ошибка сборки каталога, а не молчаливый приоритет, кроме явно задокументированного более конкретного шаблона и typed entity resolution.
3. `{application}`, `{window}`, `{monitor}` — типизированные ссылки, не произвольная строка и тем более не shell-аргумент. Перехватывать конфликт свободного параметра с отдельной буквальной командой.
4. Все шаблоны сопоставлять **целиком**. Ни поиск по подстроке, ни автоматически удалённое «не», ни подстановка близко звучащей опасной команды не допускаются.
5. Отдельные регрессионные корпуса: позитивные формы (JSON в `data/command-category-02-examples.json`), негативные, многокомандные, конфликтные и сценарии истечения контекста.
6. При расширении словарей отчёт должен фиксировать число вариантов, пересечения, неоднозначности и отвергнутые фразы. Расширение словаря не должно автоматически расширять системные разрешения.
7. Многообразие голоса тестируется на транскрипциях реально выбранного STT, а не обещается по одному только текстовому тесту. Акустически похожие «сон» / «слон» не автозапускают системные функции.

## Пример (не исполняемый системный реестр)

```json
{
  "id": "app.open",
  "families": [
    ["{openVerb}", "{application}"],
    ["{application}", "{openVerb}"],
    ["пожалуйста", "{openVerb}", "{application}"]
  ],
  "lexicon": { "openVerb": ["открой", "запусти", "включи"] },
  "slots": { "application": "verified:ApplicationRegistryID" }
}
```

Это декларация желаемой грамматики. Текущий `compileRegistry` принимает уже развёрнутые строковые шаблоны и ещё не поддерживает такой семейный синтаксис. Не подключать демонстрационные Desktop-навыки к браузеру в качестве имитации.
