# Архитектура LUMEN (без генеративного ИИ)

## Фактическое состояние

```text
index.html / styles.css
         |
      js/app.js ── Web Speech API, TTS, локальная история, UI
         |
    js/commands.js ── старые ограниченные демокоманды (пока неизменны)

js/command-engine.js ── отдельный, протестированный фундамент для будущего каталога
tests/command-engine.test.js ── изолированные тестовые фикстуры (не каталог)
```

Новый движок ещё не подключён к веб-интерфейсу: категория 01 (`docs/COMMAND_CATALOG.md`) и категория 02 (`docs/COMMAND_CATEGORY_02.md`) зафиксированы как спецификации, но их обработчики и переходы состояний не реализованы. В `data/command-category-02-examples.json` хранится проверочный корпус фраз, а не реестр исполняемых команд. Веб-демо продолжает работать по предыдущей логике. Никаких запросов к LLM, передачи API-ключей, самостоятельной генерации действий нет.

## Целевой поток после согласования

```text
   Кнопка / текст / локальный Desktop STT
                    |
            нормализованная фраза
                    |
      Реестр утверждённых команд + matcher
                    |
            типизированные параметры
                    |
       проверка capability / разрешения
                    |
          подтверждение при необходимости
                    |
         обработчик навыка / адаптер ОС
                    |
     проверенный результат или ошибка → ответ / TTS
```

Граница между распознаванием голоса и обработкой команд строгая. Распознавание речи само по себе может использовать обученную акустическую модель; цель «без ИИ» здесь означает отсутствие **генеративного ИИ и автономных решений**. Для Desktop требуется отдельно выбранный офлайн STT. Текущий браузерный Web Speech API в некоторых браузерах может использовать внешнюю обработку и не является гарантированно офлайн.

## Контракт командного движка

`compileRegistry(definitions)` валидирует уникальные ID, шаблоны и схемы параметров. `matchCommand(registry, utterance)` возвращает совпадение либо один из статусов `unknown`, `invalid_parameters`, `ambiguous`. `createCommandEngine` добавляет разрешения, поддержку подтверждения в течение ограниченного времени и вызов явного обработчика.

Статусы выполнения: `success`, `failed`, `unsupported`, `forbidden`, `pending_confirmation`, `cancelled`, `expired` и статусы сопоставления. Ни права, ни возможности не подразумеваются по умолчанию. Результат обработчика должен быть объектом с `ok: true` и непустым `message`. Это API для будущих адаптеров, **не реальное управление ОС**.

## Текущая безопасность Web Preview

- История до 50 последних сообщений в `localStorage`, без собственного сервера и аналитики.
- Микрофон включается только по действию пользователя; нет постоянного фонового прослушивания.
- Озвучивание выключено по умолчанию.
- Интерфейс использует `textContent` для пользовательских сообщений.
- На GitHub Pages нельзя хранить приватные ключи и нельзя запускать произвольные системные команды.
- Подтверждения в новом движке рассчитаны только на активную локальную сессию. До появления Desktop-адаптера и каталога нельзя заявлять о реальной защите системных действий.

## Следующий шаг

Опираясь на обе спецификации, проектировать реализацию категорий 01 и 02 отдельно от формирования последующих категорий. Вариативность фраз описана в `docs/VOICE_VARIANTS.md`. Не объявлять утверждённую спецификацию работающим функционалом. Без GitHub Actions, сайт разворачивается через Pages → Deploy from a branch, `main` / `(root)`.

Запуск локального сайта: `python3 -m http.server 8000`; тесты: `npm test` с Node.js 20+.
