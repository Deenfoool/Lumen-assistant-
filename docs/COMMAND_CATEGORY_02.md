# LUMEN — категория 02. Управление компьютером и приложениями

Спецификация **v0.2 (утверждена как проектное решение)** · 2026-10-15. **Реализация в Desktop не выполнена.** Команды здесь — требования, а не обещание работы на GitHub Pages. Без генеративного ИИ.

## Решения по умолчанию

- Основная целевая платформа: **Windows 11**; Windows 10 — только после отдельного тестирования. Linux в будущем через отдельный OS-адаптер, не через изменение командных ID.
- Автоматическое обнаружение приложений (из стандартных системных источников) → локальный Application Registry, который можно исправлять вручную. Никакой запуск по неподтверждённому пути, найденному в произвольной речи.
- Полноценное управление окнами, поддержка нескольких мониторов. Реальные возможности зависят от прав ОС и конкретного окна.
- Сон, выключение, перезагрузка и выход из аккаунта **всегда** требуют подтверждения по утверждённому протоколу категории 01. Блокировка сеанса — без отдельного подтверждения.
- Короткие ответы только после проверки выполненной операции. Срок продолжения диалога и срок подтверждения — отдельные интервалы по 15 секунд (категория 01).
- Команды не используют LLM, произвольные терминальные строки, рефлексивный обход прав, принудительное закрытие или выполнение цепочек без отдельного Scenario Engine.

## Вариативность без угадывания

Не плодим по 40 отдельных обработчиков для одного действия. Используем слои:

1. Строгая нормализация (регистр, «ё/е», пробелы, допустимая пунктуация); префикс «Люми» снимается только если он распознан как начало обращения.
2. Семейства грамматических конструкций: прямой порядок («открой Steam»), обратный («Steam открой»), вежливый («пожалуйста, открой Steam»), разговорные явные формулы («запусти стим»), если они однозначны. Слова «пожалуйста», «можешь», «мне» не удаляем глобально — только как разрешённые конструкции.
3. Словари синонимов действий и объектов с ограниченной областью: «стим» → Steam только в Application Registry; «эксплорер» должен уточнять браузер или Проводник при реальной коллизии. Произвольных синонимов через расстояние Левенштейна нет.
4. Типизированные сущности: приложение как ID реестра, окно как конкретный проверенный handle, экран как доступный display ID, местоимение как ссылка на ещё существующий объект в активном контексте.
5. Команды из категории 01, подтверждение/отмена и отрицание имеют приоритет над опасными операциями. Один неоднозначный результат → вопрос, **ноль побочных эффектов**. Составное высказывание без утверждённого сценария не исполняется частями.
6. После каждого изменения словарей — регрессионный прогон всех фраз, конфликтующих и отрицательных примеров; точность безопасного отказа важнее количества срабатываний.

Не применять «не» как стоп-слово. «Не выключай компьютер» не равно «Выключи компьютер». Не допускать совпадение по подстроке в длинных фразах. Для особенно рискованных команд запрещено автоматическое приблизительное совпадение по звучанию.

## Разрешения и системные адаптеры

| Группа | Capability / разрешение | Проверка результата |
|---|---|---|
| Приложения | `desktop.apps` + локальный реестр разрешённых целей | Окно/процесс обнаружен, либо ОС явным образом приняла запуск; различать «запускается» и «открыла» |
| Окна | `desktop.windows` + принадлежность выбранного окна пользовательской сессии | Адаптер подтвердил новое состояние и актуальность окна; защищённые окна могут отказать |
| Питание | `desktop.power` и явный pendingAction; запрет на `force` | ОС приняла штатный запрос. Не обещать, что машина непременно выключилась |
| Скриншот | `desktop.capture` + выбранная пользователем локальная папка | Файл действительно записан и доступен; никогда не отправлять автоматически |
| Буфер | `desktop.clipboard.read` по явному обращению, отдельное право | Только текст; показать в UI, не озвучивать и не сохранять историю автоматически |
| Батарея / аптайм | `desktop.telemetry.read` | Фактические доступные данные ОС, без имитаций |

Не передавать распознанное имя приложения напрямую в shell, PowerShell, CMD или URI без валидации. Application Registry хранит верифицированный идентификатор цели и возможные алиасы, не свободную строку запуска от модели или голосового ввода. Автоматически обнаруженное приложение не означает неограниченного разрешения на все его действия.

### Уточнения, границы и восстановление

- `app.open`: уже запущенный экземпляр по возможности активировать; если это нарушает поведение конкретного приложения — штатно открыть и сообщить. `app.focus` **не запускает** отсутствующую программу.
- `app.close` и `window.close` отправляют штатный запрос закрытия. При диалоге о несохранённых данных остановиться и передать выбор пользователю; не форсировать. При нескольких совпадениях — «Какое окно?».
- `window.minimize_all` не завершает процессы. `window.previous` не означает повтор последней команды и использует историю валидных окон.
- `window.move_monitor`: слова «второй», «два», «2» обозначают один проверенный display ID, но нумерация должна соответствовать видимой карте мониторов пользователя. «Другой» — только когда альтернативный монитор ровно один.
- Контекст «его», «это окно», «там» доступен только в 15-секундном активном диалоге и при живом, однозначном объекте. Нельзя восстановить устаревший handle по похожему названию без проверки.
- Сон/выключение/перезагрузка/выход: вопрос содержит целевое действие, таймер подтверждения начинается после вопроса, «Да» не подтверждает, только «Подтверждаю» / «Да, подтверждаю». Успешная отправка штатного системного запроса описывается как «Запрос отправлен», а не «Компьютер уже выключен».
- `system.clipboard_read`: показать текст по явному запросу, не сохранять его в историю, телеметрию или TTS. Для озвучивания приватного содержимого потребуется отдельная специально утверждённая команда.
- Для разных пользовательских окон с одним названием или защищённых системных окон — уточнение или отказ, а не угадывание/повышение привилегий.

| «выключи свой голос» | Не превращать в действие: category 01 voice.mute, not system shutdown |

## Приёмка категории 02

- Каждое положительное высказывание корпуса приводит к одному и тому же ID со структурированными параметрами; если имя не зарегистрировано, — запрос уточнения/отказ, а не запуск произвольного пути.
- Запрет опасного преобразования фраз при отрицании, коллизиях, ошибках STT, неизвестной цели, недоступном capability и отсутствии permission.
- Проверка Windows 11 на реальных приложениях, системных окнах, двух и более мониторах, несохранённом документе, отсутствии батареи и отклонённом выключении.
- Сквозные тесты: голос → текст → намерение → сущности → разрешение → подтверждение при необходимости → OS adapter → проверенный ответ. Без установленного Desktop-клиента это **не выполнено**.
- Полное разграничение категории 01: «Отключи свой голос» не выключает компьютер; «Говори тише» не меняет громкость ОС; системное «Отмена» не отменяет уже исполненный запрос задним числом.

**Статус:** дизайн категории 02 утверждён по делегированному пользователем решению. Имплементация и тесты на реальной ОС — `not started`. Следующие категории требуют отдельной проектной спецификации.
