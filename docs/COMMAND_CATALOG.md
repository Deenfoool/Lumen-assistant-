## Категория 01. Управление Люми

### 1. Зафиксированные настройки

| Настройка | Решение |
|---|---|
| Имя и ключевое слово | «Люми»; допустимое обращение «Эй, Люми» |
| Режим активации | Локальная голосовая активация (явно включается в Desktop) + переназначаемая горячая клавиша |
| Состояние сразу после установки | Голосовая активация выключена до разрешения пользователя |
| Диалог без повторения имени | Да, 15 секунд после окончания ответа/прерывания ответа; не продлевается из-за шума |
| Ответ на обычное действие | Короткий, но только по проверенному результату |
| Перебивание ответа | Да — требование для Desktop; при техническом отсутствии duplex/barge-in показывать ограничение и предоставлять клавишу/кнопку |
| Язык | Русский |
| Голос и системная громкость | Независимые логические настройки; не менять системную громкость командой «Говори тише» |
| Срок подтверждения | 15 секунд, отдельный таймер после завершения/прерывания вопроса о подтверждении |
| Аудиозапись | Постоянно не хранить |
| Генеративный ИИ | Не использовать |

Горячую клавишу выбираем после определения Desktop-платформы и проверки конфликта с системой: сочетание Alt+Space пока **не утверждено**. Отказ ОС в доступе к микрофону нельзя обойти горячей клавишей.

### 2. Состояния (две независимые оси)

**Доступ к микрофону:** MIC_OFF — микрофон явно отключён пользователем, запись и детектор выключены; MANUAL_IDLE — микрофон не захватывается и wake выключен по настройке, доступна ручная активация; WAKE_ARMED — локальный детектор ключевого слова ожидает обращение; ACTIVE — начат диалог/захват следующей команды. Из MIC_OFF вернуть звукозахват можно только явным действием через интерфейс или горячую клавишу (при наличии разрешения ОС). После «Отдыхай» ACTIVE → WAKE_ARMED, если wake-режим включён, иначе MANUAL_IDLE.

**Ход диалога:** IDLE, LISTENING, PROCESSING, SPEAKING. Отдельно хранится **pendingAction**: отсутствует либо содержит конкретный ID, параметры, срок подтверждения и статус. Нельзя моделировать SPEAKING и ожидание подтверждения как взаимоисключающие состояния: вопрос может озвучиваться, пока операция остаётся неподтверждённой.

Приоритет обработки: экстренное выключение микрофона и прерывание речи → отмена/подтверждение ожидающей операции → обычные команды. Детектор ключевого слова не является командным исполнителем; он лишь активирует приём. Префикс «Люми, ...» удаляется ровно один раз **только в начале распознанного высказывания**. Слово внутри фразы не удалять. «Люми, пока» должно обрабатываться одной фразой и не активировать помощницу заново.

**Таймер 15 секунд:** после завершения короткого ответа или его прерывания открывается окно для следующей команды. Для чистого обращения «Люми» окно начинается после сигнала готовности. Если команда произнесена сразу с именем, исполнять её в рамках одного высказывания. По истечении окна → ожидание (без ложного ответа «Готово»). Не включать принудительно постоянную запись только для удобства контекста.

### 3. Утверждённые команды и точное назначение

Только нижеперечисленные фразы/явно перечисленные синонимы. Парсер без LLM не должен делать вид, что понимает произвольную речь. ID постоянен; расширение фраз проходит проверку конфликтов. В таблице «Люми, ...» означает допустимый префикс при обращении, если микрофон/голосовая активация включены.

| ID | Фраза / синонимы | Эффект и короткий ответ |
|---|---|---|
| lumi.wake | «Люми», «Эй, Люми» | Событие детектора ключевого слова, не исполняемая системная команда; ACTIVE, сигнал/«Слушаю» |
| lumi.sleep | «Отдыхай», «До связи», «Пока», «Пока, Люми» | Завершить диалог, отменить pendingAction; «До связи»; возврат в режим ожидания |
| lumi.mic_off | «Отключи микрофон», «Не слушай меня» | Отключить захват и wake-детектор, отменить pendingAction; «Микрофон отключён» |
| lumi.status | «Ты здесь?», «Ты меня слышишь?» | Назвать реальное состояние, напр. «Да, слушаю»; при MIC_OFF голосом недоступно |
| lumi.stop_speech | «Стоп», «Замолчи», «Хватит» | Сразу прервать TTS; **не** отменять pendingAction и уже выполняемую операцию |
| lumi.cancel | «Отмена», «Отмени» | Отменить pendingAction или ещё не начатое отменяемое действие; если уже выполнено — честно сообщить, что назад не возвращено |
| lumi.repeat | «Повтори», «Что ты сказала?», «Повтори вопрос» | Повторить последний ответ/актуальный вопрос, **никогда не повторять системное действие** |
| lumi.help | «Что ты умеешь?», «Помощь» | Коротко перечислить только действительно доступные функции текущего устройства |
| lumi.show_commands | «Покажи все команды», «Открой список команд» | Показать каталог в UI с маркерами «доступно/в разработке» |
| lumi.confirm | «Подтверждаю», «Да, подтверждаю» | Только при действующем pendingAction: подтвердить **эту** операцию и ровно один раз передать её исполнителю |
| lumi.reject | «Нет», «Отказываюсь» | Только при pendingAction: отклонить эту операцию; «Отменено» |
| voice.volume_up | «Говори громче» | Повысить громкость TTS Люми на 10 п. п. до максимума 100%; «Хорошо» |
| voice.volume_down | «Говори тише» | Снизить громкость TTS Люми на 10 п. п. до минимума 0%; «Хорошо» |
| voice.speed_up | «Говори быстрее» | Повысить скорость TTS на 0,1x, максимум 2,0x; «Хорошо» |
| voice.speed_down | «Говори медленнее» | Понизить скорость TTS на 0,1x, минимум 0,5x; «Хорошо» |
| voice.speed_reset | «Говори нормально» | Скорость TTS 1,0x; «Хорошо» |
| voice.mute | «Отключи свой голос», «Отвечай текстом» | Выключить TTS Люми, не выключая микрофон и системный звук; показать «Голос выключен» в UI |
| voice.unmute | «Включи свой голос», «Отвечай голосом» | Включить TTS Люми; «Голос включён» |

Итого **18 записей**, из них одна — событие голосовой активации, остальные — контекстные/обычные команды. Команды «Слушай меня» / «Люми, слушай» — синонимы запроса на повторный приём в активном сеансе, **не отдельный ID**; они открывают очередное окно прослушивания. Точное продолжение прерванной речи («Продолжай») **не входит** в эту версию: разные TTS-движки не гарантируют восстановление с нужной позиции.

Настройки будущего TTS-профиля: громкость 80%, скорость 1,0x. Громкость 0% технически равна отсутствию слышимого ответа, но не меняет настройку voice.mute; оба состояния можно восстановить через UI. Если TTS не умеет программно контролировать громкость или скорость — вернуть «Настройка недоступна», не менять громкость всей ОС и не заявлять успех.

### 4. Подтверждения, отмена и конфликты

1. На pendingAction приоритет имеют «Подтверждаю» / «Да, подтверждаю», «Нет» / «Отказываюсь», «Отмена» / «Отмени», «Повтори вопрос», «Стоп», «Отключи микрофон» и «Отдыхай». Одиночное «Да» **не является подтверждением**. При отсутствии pendingAction «Нет» не становится универсальной отменой, а «Подтверждаю» ничего не исполняет.
2. Вопрос подтверждения должен явно назвать конкретное действие и существенные параметры. Срок 15 секунд начинается после завершения или прерывания озвучивания вопроса (или показа его в текстовом режиме). При истечении срока действие не исполняется; пользователь повторяет запрос.
3. «Повтори вопрос» повторно озвучивает/показывает тот же вопрос без повторного запуска действия; не подменять ID/аргументы. После повторного вопроса окно подтверждения возобновляется на 15 секунд. Любая новая **другая** команда снимает старое pendingAction перед обработкой новой.
4. «Стоп» во время вопроса только останавливает TTS; pendingAction остаётся с видимым таймером подтверждения. «Отдыхай» и «Отключи микрофон» закрывают pendingAction.
5. Действие не может получить ответ «Готово» до проверенного результата. Для необратимого или уже исполненного действия «Отмена» не делает ложный откат. Дополнительное UI-подтверждение для особо рискованных функций определяется в категориях таких функций.
6. Команда «Отключи свой голос» не отключает микрофон; команда «Отключи микрофон» не равна отключению голоса. «Говори тише» относится только к Люми; изменение громкости компьютера будет отдельной категорией.
7. Распознавание голоса во время TTS требует подавления акустического эха и фильтрации собственного голоса Люми. Если выбранный движок не поддерживает надёжное голосовое перебивание, нужно отображать ограничение и сохранить доступное перебивание кнопкой/горячей клавишей, а не создавать фиктивную поддержку.

### 5. Требования к реализации (категория согласована, код ещё не выполнен)

- Для Desktop ключевое слово желательно распознавать локально и только после явного включения пользователем. Web Speech API текущего веб-демо **не гарантирует офлайн**, и фоновая активация на GitHub Pages не обещается.
- Один общий текстовый маршрут для кнопки, горячей клавиши и распознанной речи; wake-event от STT отделён от каталога исполняемых команд.
- Префиксное распознавание, контекстный приоритет, таймеры и отключение микрофона должны быть протестированы не только обычными unit-тестами парсера, но и тестами переходов состояний.
- Ручной ввод и управление настройками через UI доступны при MIC_OFF. Разрешения ОС никогда не обходить.
- В веб-превью при отсутствии возможностей Desktop показывать «Недоступно в веб-версии»; не объявлять перечисленные команды работающими без адаптеров и сквозной проверки.

### 6. Приёмочные сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Wake разрешён; сказать «Люми» | ACTIVE, сигнал готовности |
| Wake запрещён или MIC_OFF; произнести «Люми» | Нет скрытого запуска микрофона |
| «Люми, пока» | Один переход в ожидание; имя внутри фразы не запускает повторное пробуждение |
| Ответ завершён; 15 секунд тишины | ACTIVE → режим ожидания |
| Во время ответа сказать «Стоп» | Немедленная остановка TTS; pendingAction, если есть, не отменён |
| Во время ожидаемого подтверждения сказать только «Да» | Не выполнять действие |
| «Подтверждаю» без pendingAction | Не выполнять действие |
| «Повтори» после выполненного действия | Повторить только ответ, не повторять действие |
| «Нет» при ожидаемом подтверждении | Отменить только ожидаемую операцию |
| Время подтверждения истекло | Не выполнять действие даже после позднего «Подтверждаю» |
| «Отключи микрофон», затем «Люми» | Нет голосовой реактивации; только UI/горячая клавиша при разрешении ОС |
| «Говори тише» | Системная громкость не меняется |
| «Отвечай текстом», затем «Отвечай голосом» | TTS выключается и вновь включается; микрофон сам по себе не меняет состояние |
| Движок не поддерживает голосовое перебивание | Честный статус ограничений, горячая клавиша/кнопка доступны |

**Граница фиксации:** категория 01 имеет согласованные требования, но не считается implemented/tested. Категория 02 описана в отдельном документе как проектная спецификация; реализация обеих категорий ещё не выполнена.
